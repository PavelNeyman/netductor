## Проблемы сейчас

1. Три верхних режима (Installer / Control / Settings) смешивают разовый деплой и day-2.
2. Вкладки Installer равнозначны — редко нужны все сразу.
3. Control — плотный каталог API без иерархии.
4. Jobs легко не заметить (сейчас: бейдж в шапке); лог — стена текста.
5. Визуально — «форма-суп», слабая иерархия и empty states.

## Вариант A — «Мастер дома + Ops» (рекомендуем)

| Зона | Роль |
|--|--|
| **Home** | 3 карточки: *Новый fleet/нода*, *OpenWrt*, *Day-2 на primary* |
| **Active job** | Липкая панель: статус, cancel, хвост лога |
| **Ops** | Operate с группами слева (Status, VPN, Edge, DNS, Backup, Advanced) |
| **Settings** | Только подключение и язык |

**Плюсы:** совпадает с моделью «настройка vs работа».  
**Минусы:** перестановка панелей в `index.html` (1–2 прохода).

---

## Вариант B — «Сайдбар (app shell)»

Классика: слева разделы, справа контент, сверху lang + jobs + update.

**Плюсы:** привычно, масштабируется.  
**Минусы:** больше вёрстки; мобильный collapse.

---

## Вариант C — «Минимальный Mac-first»

Web только OpenWrt + Jobs + tunnel/session; Fleet/Primary/Secondary — TUI/CLI.

**Плюсы:** меньше путаницы.  
**Минусы:** не единый UI.

---

## Общие правила

1. Один главный CTA на экран.  
2. Jobs — источник правды для долгой работы.  
3. Prefill из `operator.conf` с подсказкой.  
4. Empty states с следующим шагом.  
5. EN/RU только через `data-i18n`.
