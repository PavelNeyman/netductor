# Дизайн OIDC / SSO (будущий multi-operator)

**Статус:** только дизайн (2026-10-12). Не реализовано.

## Цель
Опциональный хук OpenID Connect, чтобы Web UI оператора принимал идентичность от внешнего IdP вместо (или в дополнение к) локальных session-токенов. Нацелено на multi-operator сценарии позже.

## Предлагаемая форма
- Конфиг в `/etc/netductor/` или state: `oidc_issuer`, `oidc_client_id`, `oidc_client_secret` (или PKCE), `oidc_redirect_uri`.
- Поток логина: Web редиректит на IdP → callback обменивает code → маппит claims (sub / email / groups) во внутреннюю идентичность оператора.
- Сессия: всё равно выдаётся короткоживущий локальный `session`-токен (существующий пакет), привязанный к OIDC subject. Существующий `requireSession` продолжает работать.
- Маппинг: опциональный group claim → роль (viewer / operator / admin). По умолчанию любой успешный OIDC-логин получает operator.
- Fallback: локальная выдача сессии (текущий CLI / TG / Web) остаётся доступной, когда OIDC не настроен.
- TG пока остаётся только на локальных сессиях (OIDC в боте нет).

## Не цели сейчас
- Полноценный multi-tenant RBAC.
- Замена существующего session store.
- OIDC на железе или edge.

## Открытые вопросы
- Какие claims доверять для авторизации.
- Поддерживать ли одновременно session cookie и Bearer.
- Поле actor в audit: хранить OIDC sub вместо "session".

Реализация отложена до появления конкретной потребности в multi-operator.
