## 4. Security review

### 4.1 Acceptable / intentional

| Area | Assessment |
|------|------------|
| Admin API localhost | Correct for threat model |
| Agent token on :8788 | Required; tighten firewall to secondary/agent nets when possible |
| Camera TLS `InsecureSkipVerify` | Expected on LAN Tapo |
| SNI health / local probes skip verify | Lab self-signed |
| SSH password only for first provision | Documented; harden after key install |
| Clip tokens + PathUnderRoot | Good |
| VPN UUID in URIs | Inherent to VLESS; protect TG access |

### 4.2 Risks to watch

1. **World-facing :8788** — if token leaks, agent plane is exposed. Prefer nft/wg allowlist; rotate token on compromise.
2. **TG bot token** — in systemd env; not in git (good). Compromise = full operator surface.
3. **Redirect :80** — deep-link helper; keep allowlist strict (already tested in CI notes).
4. **Hosted VPS** — disk encryption for NVR segments still operator-driven; backups `.ndenc` must stay off plaintext hoster snapshots when possible.
5. **RU-direct is not anti-fingerprint** — apps that detect *VPN interface* still break; routing cannot fix that.
6. **Flow mismatch alerts** — useful; ensure they do not log full client configs.

### 4.3 Checklist (ops)

- [x] SSH key-only after provision  
- [x] Admin not public  
- [x] Blocky on localhost DNS  
- [ ] Confirm secondary firewall: only 443/22 (or custom SSH) as needed  
- [ ] Rotate any chat-pasted tokens after incidents  
- [ ] After domain change: set `NETDUCTOR_REDIRECT_BASE` + VPN advertise hosts
